THE LEDGER یک ژورنال معاملاتی تحت مرورگر است که با HTML، CSS و JavaScript ساده ساخته شده. این برنامه به بک‌اند، ساخت حساب کاربری یا مرحلهٔ Build نیاز ندارد. سوابق معاملاتی در IndexedDB مرورگر ذخیره می‌شوند و به سرور اختصاصی THE LEDGER ارسال نمی‌شوند.

## چرا THE LEDGER؟

سوابق معاملاتی اطلاعات شخصی و مهمی هستند. با THE LEDGER می‌توانی معاملاتت را ثبت و عملکردت را بررسی کنی، بدون ساخت حساب کاربری یا بارگذاری داده‌ها روی سرور برنامه. پروژه با رویکرد local-first طراحی شده و برای نگهداری داده‌ها به بک‌اند نیاز ندارد؛ بااین‌حال، چون فضای مرورگر دائمی نیست، باید مرتب بک‌آپ بگیری.

## امکانات

- **چند ژورنال معاملاتی** با بالانس، تنظیمات و فهرست گزینه‌های قابل‌تنظیم جداگانه.
- **ثبت معامله** با نتیجه‌های Win، Loss و Break-even.
- **فیلدهای خودکار معامله:** R-multiple، روز معاملاتی و Session.
- **تحلیل عملکرد:** Win Rate، Profit Factor، Expectancy، Drawdown، Streaks، Risk of Ruin و تفکیک معاملات Long و Short.
- **بررسی عملکرد** بر اساس Session، روز هفته، ساعت، نماد معاملاتی و Psychology.
- **نمایش‌های تحلیلی:** Equity Curve، تقویم معاملاتی و خلاصهٔ ماهانه.
- **چک‌لیست فارسی پیش از ورود به معامله.**
- **تم‌های ظاهری** و فهرست گزینه‌های قابل‌تنظیم.
- **بک‌آپ و بازیابی JSON** برای یک ژورنال یا تمام ژورنال‌ها.

## شروع سریع

### اجرای مستقیم

۱. مخزن را Clone کن یا دانلودش کن.  
۲. فایل `index.html` را در یک مرورگر مدرن باز کن.  
۳. یک ژورنال بساز و ثبت معاملات را شروع کن.

برای بازکردن برنامه نیازی به Build یا نصب پکیج نیست.

### اجرا با سرور محلی

به Node.js/npm نیاز داری:

```bash
npm install
npm start
```

یا اگر Python نصب است:

```bash
python3 -m http.server
```

بعد آدرس محلی‌ای را که سرور نمایش می‌دهد در مرورگر باز کن.

## داده‌ها، حریم خصوصی و بک‌آپ

- اطلاعات ژورنال در IndexedDB مرورگر با نام `LedgerTradingJournalDB` ذخیره می‌شود؛ برنامه آن‌ها را به بک‌اند THE LEDGER ارسال نمی‌کند.
- **ذخیره‌سازی مرورگر بک‌آپ نیست.** پاک‌کردن داده‌های سایت یا ازدست‌رفتن پروفایل مرورگر ممکن است ژورنال‌ها را حذف کند.
- اطلاعات بین مرورگرها یا دستگاه‌های مختلف به‌صورت خودکار همگام‌سازی نمی‌شوند.
- مرتب خروجی JSON بگیر و نسخه‌های پشتیبان را در محل امن نگه دار.
- پیش از اتکا به یک بک‌آپ، بازیابی آن را آزمایش کن.
- فایل‌های JSON خروجی را مثل سوابق مالی خصوصی نگهداری کن.

برنامه هنگام بارگذاری یا Import، تنظیمات قدیمی‌تر را به‌صورت خودکار مهاجرت می‌دهد. پیش از آزمایش Import یا تغییرات مهم، یک نسخهٔ پشتیبان جداگانه نگه دار.

## تنظیمات

- **آستانهٔ Break-even — `BE_RISK_FRACTION`** در فایل `js/02-theme-utils.js`: در حالت Auto، اگر قدر مطلق P&L کمتر یا مساوی این نسبت از ریسک باشد، نتیجه Break-even محسوب می‌شود. مقدار پیش‌فرض `0.05`، یعنی ۵٪ ریسک است.
- **بازه‌های Session — `SESSION_RANGES`** در فایل `js/02-theme-utils.js`: برای تعیین Session از روی زمان ورود استفاده می‌شوند. این بازه‌ها را با منطقهٔ زمانی ساعاتی که وارد می‌کنی هماهنگ کن.

در حالت Auto، معاملات Break-even در محاسبهٔ Win Rate شمرده نمی‌شوند، اما در P&L و Expectancy لحاظ می‌شوند.

## تست‌ها

پروژه یک تست اولیهٔ Playwright دارد که برنامه را در Chromium باز می‌کند و مسیرهای اصلی ژورنال، تنظیمات و داده‌های معامله را بررسی می‌کند.

```bash
npm install
npm test
```

Playwright به یک مرورگر Chromium سازگار نیاز دارد. اگر از مرورگر نصب‌شدهٔ محلی استفاده می‌کنی، طبق توضیحات فایل `tests/smoke.test.js` مسیر اجرایی آن را در متغیر `CHROMIUM_PATH` قرار بده.

## انتشار روی GitHub Pages

Workflow مربوط به GitHub Actions در مسیر `.github/workflows/pages.yml` قرار دارد.

۱. تغییراتت را به شاخهٔ `main` ارسال کن.  
۲. در تنظیمات مخزن وارد **Settings → Pages** شو.  
۳. منبع انتشار را روی **GitHub Actions** قرار بده.  
۴. نتیجهٔ انتشار را در زبانهٔ Actions بررسی کن.

## مشارکت

گزارش باگ، اصلاح مستندات و بهبودهای هدفمند مورد استقبال‌اند.

۱. مشکل یا پیشنهادت را در یک Issue توضیح بده.  
۲. مخزن را Fork کن و یک Branch بساز.  
۳. تغییرات را محدود و هدفمند نگه دار و دلیلشان را بنویس.  
۴. هنگام تغییر رفتار برنامه، دستور `npm test` را اجرا کن.  
۵. یک Pull Request همراه با خلاصه و توضیح تست‌ها ارسال کن.

لطفاً اصول اصلی پروژه را حفظ کن: داده‌های local-first، عدم نیاز به بک‌اند و اجرای ساده در مرورگر.
